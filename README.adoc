= commons-connect

link:README_zh.adoc[中文] | English

== Introduction

=== Features

commons-connect provides simple APIs for connecting to devices and sending commands. Main features:

* Supports SSH, TELNET and SHELL connections, and can be extended
* Supports configuring the success/fail flags and the timeout of command execution
* Supports paging commands such as --More--
* Supports command chains, and stops at the first command whose fail flag matches
* Supports keep alive

=== Requirements

* JDK 1.8+

=== Installation

[source,xml,subs="verbatim"]
----
        <dependency>
            <groupId>io.github.pxzxj</groupId>
            <artifactId>commons-connect</artifactId>
            <version>0.1.0</version>
        </dependency>
----

=== Quick start

A simple example
[source,java,subs="verbatim"]
----
public class StartConnect {

    public static void main(String[] args){
        ConnectionConfigurer connectionConfigurer = ConnectionConfigurerBuilder.ssh()
                                                    .host("192.168.3.1")
                                                    .port(22)
                                                    .username("root")
                                                    .password("pwd")
                                                    .successFlags("#")
                                                    .build();                 // <1>
        Connection connection = new SshConnectionFactory().createConnection(connectionConfigurer);      // <2>
        CommandConfigurer commandConfigurer = CommandConfigurerBuilder.newCommandConfigurer("df -h")
                                                                .successFlags("#")
                                                                .next("pwd")
                                                                .successFlags("#")
                                                                .build();                 // <3>
        CommandResult commandResult = connection.sendCommand(commandConfigurer);          // <4>
        System.out.println("success = " + commandResult.isSuccess());
        if(!commandResult.isSuccess()){
            System.out.println("failed command = " + commandResult.getFailCommand());
        }
        System.out.println("echo = " + commandResult.getResult());
        connection.close();                                                              // <5>
    }
}
----
<1> Build the connection configuration: protocol, device information, charset, success flags, and the commands to run after login
<2> Create the connection
<3> Build the command configuration: command text, success/fail flags, and the next command
<4> Send the command; the result tells whether it succeeded, which command failed and what the echo was
<5> Close the connection; the command configured in `preDisconnect` is sent first

== API reference

=== Connection

image::images/Connection.svg[]

link:src/main/java/io/github/pxzxj/connect/Connection.java[`Connection`] is the interface that represents a connection to a device,
once it is created `sendCommand(CommandConfigurer)` sends commands to the device and returns the echo, and `close()` must be called when the connection is no longer needed

`isConnected()` checks the connection state, and `getPostConnectOutput()` returns the echo produced when the connection was created, for example the SSH motd

There is one implementation of `Connection` per connection type; ssh, telnet and shell are supported today, see <<connection-type>> for details

=== ConnectionFactory

image::images/ConnectionFactory.svg[]

link:src/main/java/io/github/pxzxj/connect/factory/ConnectionFactory.java[`ConnectionFactory`] creates a `Connection` with `createConnection(ConnectionConfigurer)`,
and `supports(ConnectionConfigurer)` makes it a strategy, which is inspired by `HandlerMethodArgumentResolver` of Spring MVC

=== ConnectionConfigurer

image::images/ConnectionConfigurer.svg[]

link:src/main/java/io/github/pxzxj/connect/ConnectionConfigurer.java[`ConnectionConfigurer`] holds the information needed to create a connection, for example the common host, port, username and password fields,
the properties differ per connection type, see <<usage>>,
instances are usually created with link:src/main/java/io/github/pxzxj/connect/ConnectionConfigurerBuilder.java[`ConnectionConfigurerBuilder`]

=== CommandConfigurer

image::images/CommandConfigurer.svg[]

link:src/main/java/io/github/pxzxj/connect/CommandConfigurer.java[`CommandConfigurer`] describes a command to execute, `command` is the command text,
`successFlags` and `failFlags` are the success and fail flags of the command: as soon as `successFlags` or `failFlags` appears in the echo the wait ends and the command is marked as succeeded or failed,
and when both of them appear the command counts as failed,

when neither of them ever appears in the echo the wait ends when the time configured through `timeoutMilliSeconds` is reached, and `timeoutMilliSeconds` defaults to 5s,
when neither `successFlags` nor `failFlags` is configured the call simply waits for `timeoutMilliSeconds` before returning

`enter` is the enter key appended to the command, it defaults to `\n` and can be adjusted to what the device supports

The echo of some commands is printed page by page, the `more` command on Linux for example; `moreFlag` and `moreCommand` can be configured to page through it automatically, so that the whole echo is fetched at once

`commandFunction` and `next` are meant for command chains, `next` is the command to execute afterwards, while `commandFunction` covers the dynamic case and builds a command from the echo of the previous command; note that a command is executed only when the previous one succeeded

instances are usually created with link:src/main/java/io/github/pxzxj/connect/CommandConfigurerBuilder.java[`CommandConfigurerBuilder`]

=== CommandResult

image::images/CommandResult.svg[]

link:src/main/java/io/github/pxzxj/connect/CommandResult.java[`CommandResult`] is the return value of `sendCommand(CommandConfigurer)`, `isSuccess()` tells whether the command succeeded, `getResult()` returns the echo, and `getFailCommand()` returns the configuration of the command that failed

== Connection types

`commons-connect` supports the ssh, telnet and shell types by default, and other types can be implemented against the API above,
a shell connection uses `cmd.exe` on Windows and `/bin/bash` on other systems by default,
and another shell can be selected through the `shellPath` property of `ConnectionConfigurer`, for example `powershell.exe` on Windows

As the image below shows, these three connection types still rely on other libraries under the hood, `commons-connect` only wraps them into a simpler and easier API

== Usage and examples

=== SSH password login

Log in with the `username` and `password` properties, `port` can be omitted when it is 22, and `successFlags` is the flag that appears in the echo after a successful login

[source,java,subs="verbatim"]
----
ConnectionConfigurer connectionConfigurer = ConnectionConfigurerBuilder.ssh()
        .host("192.168.3.1")
        .port(22)
        .username("root")
        .password("password")
        .successFlags("#")                                                          // flag of a successful login
        .build();

Connection connection = new SshConnectionFactory().createConnection(connectionConfigurer);
----

=== SSH public key login

Log in with a private key by setting the `privateKey` property, and when the key itself has a password set it through the `passphrase` property

[source,java,subs="verbatim"]
----
ConnectionConfigurer connectionConfigurer = ConnectionConfigurerBuilder.ssh()
        .host("192.168.3.1")
        .username("root")
        .privateKey("/home/pxzxj/.ssh/id_rsa")
        .passphrase("passphrase")                       // can be omitted when the key has no password
        .successFlags("#")
        .build();

Connection connection = new SshConnectionFactory().createConnection(connectionConfigurer);
----

=== TELNET

Some network devices implement their own authentication procedure over the TELNET protocol, configure that procedure in `postConnect`, and `port` can be omitted when the default port 23 is used

[source,java,subs="verbatim"]
----
ConnectionConfigurer connectionConfigurer = ConnectionConfigurerBuilder.telnet()
        .host("192.168.3.1")
        .port(31114)
        .successFlags("RETCODE = 0")
        .postConnect(CommandConfigurerBuilder.newCommandConfigurer("LGI:OP=\"user\",PWD=\"pwd\";")
                .successFlags("RETCODE = 0")
                .next("REG NE:Name=\"ne1\";")
                .successFlags("RETCODE = 0")
                .build())
        .preDisconnect(CommandConfigurerBuilder.newCommandConfigurer("UNREG NE:Name=\"ne1\";")
                .successFlags("RETCODE = 0")
                .next("LGO:OP=\"user\";")
                .successFlags("RETCODE = 0")
                .build())
        .build();

Connection connection = new TelnetConnectionFactory().createConnection(connectionConfigurer);
----

=== Default SHELL

[source,java,subs="verbatim"]
----
ConnectionConfigurer connectionConfigurer = ConnectionConfigurerBuilder.shell()
        .charset("GBK")                             // echo charset of cmd.exe on a Chinese Windows
        .successFlags(">")
        .postConnect(CommandConfigurerBuilder.newCommandConfigurer("echo hello")
                .enter("\r")                        // \r is required on Windows, see below
                .successFlags(">")
                .build())
        .build();

Connection connection = new ShellConnectionFactory().createConnection(connectionConfigurer);
----

=== powershell

Set the `shellPath` property to `powershell.exe`; note that `powershell.exe` requires the `enter` key to be set to `\r` explicitly

[source,java,subs="verbatim"]
----
ConnectionConfigurer connectionConfigurer = ConnectionConfigurerBuilder.shell()
        .shellPath("powershell.exe")
        .charset("GBK")
        .successFlags(">")
        .postConnect(CommandConfigurerBuilder.newCommandConfigurer("echo hello")
                .enter("\r")
                .successFlags(">")
                .build())
        .build();
----

=== KeepAlive

The keepAlive properties of `ConnectionConfigurer` implement keep alive for a connection,
the principle is simple: when the user has not sent a command for `keepAliveInterval`, a `keepAliveCommand` is sent automatically, and the connection waits for `keepAliveWaitStr` with `keepAliveWaitTimeout` as the timeout

Setting `keepAliveCommand` is enough to enable keep alive, the other three fields have default values,
note that unlike a normal command no `enter` is appended to `keepAliveCommand`, so `\r` or `\n` has to be included explicitly in the command when it is needed

[source,java,subs="verbatim"]
----
ConnectionConfigurer connectionConfigurer = ConnectionConfigurerBuilder.ssh()
        .host("192.168.3.1")
        .username("root")
        .password("password")
        .successFlags("#")
        .keepAliveCommand("pwd\n")                        // command sent while idle
        .keepAliveWaitStr("#")                          // echo awaited for the keep alive command
        .keepAliveInterval(60000)                       // idle time before sending, in milliseconds, 60000 by default
        .keepAliveWaitTimeout(2000)                     // timeout of the awaited echo, in milliseconds, 2000 by default
        .build();
----

NOTE: `keepAliveWaitStr` defaults to a string that never appears in the echo, so the keep alive result is only known when the wait times out; setting it to the real prompt of the device is recommended

=== CompositeConnectionFactory

`CompositeConnectionFactory` is the composite implementation of `ConnectionFactory`, it creates connections of different types

[source,java,subs="verbatim"]
----
ConnectionFactory connectionFactory = new CompositeConnectionFactory(
        new SshConnectionFactory(), new TelnetConnectionFactory(), new ShellConnectionFactory());
Connection connection = connectionFactory.createConnection(connectionConfigurer);
----

=== Sending a command

`sendCommand()` returns a `CommandResult` that holds whether the command succeeded, the command that failed and the echo

[source,java,subs="verbatim"]
----
CommandConfigurer commandConfigurer = CommandConfigurerBuilder.newCommandConfigurer("df -h")
        .successFlags("#")                                      // a match in the echo means success
        .failFlags("No such file or directory")                 // a match in the echo means failure, optional
        .timeoutMilliSeconds(5000)                              // timeout of the awaited flags, in milliseconds, 5000 by default
        .build();

CommandResult commandResult = connection.sendCommand(commandConfigurer);
System.out.println("success = " + commandResult.isSuccess());
System.out.println("echo = " + commandResult.getResult());
if(!commandResult.isSuccess()) {
    System.out.println("failed command = " + commandResult.getFailCommand());
}
----

=== Paging with More

[source,java,subs="verbatim"]
----
CommandConfigurer commandConfigurer = CommandConfigurerBuilder.newCommandConfigurer("more bigfile")
        .successFlags("#")
        .moreFlag("--More--")                       // this flag in the echo means another page is available
        .moreCommand(" ")                           // command sent repeatedly during the wait, a space by default
        .build();
----

NOTE: It is hard for `commons-connect` to send `moreCommand` only when `moreFlag` shows up like a human does, therefore `moreCommand` is sent repeatedly during the wait

=== Command chains

Configure the next command with `next()`, several commands share a single `sendCommand()` call, and the chain stops at the first fail flag without executing the remaining commands

[source,java,subs="verbatim"]
----
CommandConfigurer commandConfigurer = CommandConfigurerBuilder.newCommandConfigurer("cd /opt")
        .successFlags("#")
        .next("ls")                                 // executed only after the previous command succeeded
        .successFlags("#")
        .next("cat app.log")
        .successFlags("#")
        .build();                                   // build() returns the first command
----

NOTE: A chain can also be assembled with `CommandConfigurer.setNext()`, in that case `CommandResult.getResult()` returns the echo of the whole chain

=== commandFunction

`commandFunction` builds a command from the echo of the previous command, which is its input

[source,java,subs="verbatim"]
----
CommandConfigurer listFiles = CommandConfigurerBuilder.newCommandConfigurer("ls /opt")
        .successFlags("#")
        .build();
CommandConfigurer catFirstFile = CommandConfigurerBuilder
        .newCommandConfigurer(echo -> "cat /opt/" + echo.trim())        // <1>
        .successFlags("#")
        .build();
listFiles.setNext(catFirstFile);

connection.sendCommand(listFiles);
----
<1> Take the file name out of the echo of `ls` and build the next command from it
